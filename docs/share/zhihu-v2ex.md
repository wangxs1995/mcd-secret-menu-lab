## 正文

### 起因

麦当劳中国今年开放了官方 MCP Server（`mcp.mcd.cn`，Streamable HTTP，35 个工具：门店、菜单、营养、优惠券、算价、下单、积分、活动日历、主题派对……），并发起了程序员节创意开发大赛。

我没做省钱计算器，也没做热量管家——这两个赛道已经挤满了。我做的是「隐藏菜单」：薯条蘸圆筒、可乐扣冰淇淋、鸡块夹进双吉这类在社交平台上流传的吃法，一直只是截图，没人把它变成**可验证、可计算、可执行**的东西。

项目叫「麦门隐藏菜单研究所」（MCD Secret Menu Lab），开源：https://github.com/wangwengao/mcd-secret-menu-lab

### 它做什么

- 12 道隐藏吃法图鉴，每道的原料都是门店真实在售餐品
- 连上 MCP 后，拉实时菜单，校验这家店今天哪几道能做（缺什么会明说）
- 按预算 / 热量 / 时段筛方案；时段从服务器时间推断，还会读活动日历做「活动联动」
- 价格走 `calculate-price` 实时算（含优惠、取餐方式），热量按官方营养表累加
- 生成「机密档案」风格配方卡（HTML / PNG），截图即可分享
- 确认后一键 `create-order`

没有 Token 也能完整体验：离线样例是从 MCP 拉下来的真实快照，还有一个纯静态的在线演示页可以筛选、搜索、随机抽一道。

### 几个值得一说的技术点

**1. 零依赖的 MCP 客户端。** Node ≥ 18 自带 fetch，Streamable HTTP 本质就是 POST JSON-RPC、响应可能是 SSE。一百多行搞定：`initialize → notifications/initialized → tools/list → tools/call`，记得保存响应头里的 `mcp-session-id` 并在后续请求带上，429 退避重试。

**2. 返回不是纯 JSON。** 麦当劳 MCP 的工具返回是「说明文字 + JSON」的混合文本——有的是 `# API Response Information … ## Original Response {json}`，有的是展示指引里夹一段 `{"success":true,…}`，前后都有字。我写了个括号配平的 `extractJson()`，优先定位 `{"success"` 开头的业务体。

**3. 营养表是紧凑文本表格。** `list-nutrition-foods` 的 `data` 是一个字符串：`[160]{productName,energyKcal,…}:\n  中薯条,null,1210,289,…`，要自己按表头切列。

**4. 菜单名和营养名对不上。** 菜单叫「薯条 / 麦乐鸡 / 新地」，营养表叫「中薯条 / 麦乐鸡5块 / 草莓新地」。每个原料维护两组关键词；菜单匹配先完全相等、再取名称最短的包含项——否则「麦乐鸡」会命中「麦乐鸡套餐」。

**5. 时段决定菜单。** 下午拉的菜单没有早餐单品。`query-meals` 支持 `reservationDate`，传次日 08:00 就能拿到早餐菜单；离线快照由两次拉取合并，用 `dayparts` 标记。

**6. 金额单位是分。** `calculate-price` 返回 `price: 1850` 表示 ¥18.5，还会返回 `takeWayList`（堂食 / 外带），下单时要把 `takeWayCode` 带上。

**7. 数据与计算交给确定性代码，表达交给 Agent。** SKILL.md 里写死了硬规则：不臆造餐品、价格不心算、下单必须显式确认、改造动作由用户到手完成。

### 诚实的局限

v1 只做到店自取（外送要配送地址与 beCode）；随心配这类组合品没有营养数据；真实下单流程按官方 schema 接入，开发期没创建真实订单。

### 结尾

仓库里有完整的 `MCP_INTEGRATION.md`（含每次联调的 traceId）、12 张配方卡、演示页和自测。如果你也想投稿一个隐藏吃法，Issue 模板已经准备好了。
